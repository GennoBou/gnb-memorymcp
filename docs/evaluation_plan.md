# GNB MemoryMCP 評価計画書

本ドキュメントは、個人用の記憶レイヤー（MCPサーバー）である **GNB MemoryMCP** の性能・機能・価値を客観的かつ継続的に評価するための計画書です。開発フェーズごとのターゲット構成に合わせた評価方法を定義します。

---

## 1. 評価対象のシステム構成

本プロジェクトでは、開発環境から本番リリースに向けて、以下の4つの接続・データベース構成を想定し、それぞれに対して評価を行います。

| 構成名 | 接続方式 | データベース | ステータス | 評価・テストの目的 |
|---|---|---|---|---|
| **1. stdio ローカル (Dev)** | 標準入出力 (stdio) | SQLite (ローカルファイル) | 実装済 | 最も手軽なローカル動作。基本的なCRUD機能とFTS5想起精度の検証。 |
| **2. HTTP ローカル (Dev)** | HTTP サーバー | SQLite (ローカルファイル) | 実装済 | 複数クライアント連携。APIキー認証の動作確認とローカルでのAPIレスポンスタイム測定。 |
| **3. HTTP Turso (中間検証)** | HTTP サーバー | Turso (リモート libSQL) | 動作可能 | ネットワーク越しでのリモートDB接続性、ネットワーク遅延の影響、クエリ最適化の検証。 |
| **4. Lambda + Turso (本番予定)** | AWS Lambda | Turso (リモート libSQL) | **将来実装予定** | コールドスタートのレイテンシ、サーバーレス環境下でのTurso無料枠内のリソース消費効率の検証。 |

## 2. 評価軸と具体的な測定方法

### ① 機能評価 (Functionality)
すべての構成において、記憶が正しく処理・検索されるかを評価します。

*   **自動CRUDテスト (全構成共通)**:
    *   `memory_create`, `memory_list`, `memory_update`, `memory_delete` がデータ破損やエラーなく動作すること。
    *   **測定方法**: Goのユニットテスト・統合テスト (`go test ./...`) にて検証します。
*   **想起精度 (検索の質) のゴールデンセット評価**:
    *   曖昧な質問に対して、期待する過去の記憶が検索結果の上位（Top-K）にヒットするかを評価します。
    *   **測定方法**: あらかじめ評価用のダミー記憶を流し込み、テスト用クエリに対する Recall@K (ヒット率) を測定します。

### ② 性能評価 (Performance)
システムの応答速度とリソース消費の観点から評価します。

*   **APIレスポンスタイムの測定**:
    *   **1, 2, 3 の構成 (Dev / 中間検証)**: 標準入出力での通信オーバーヘッド、ローカル HTTP サーバーのレスポンスタイム、リモートDBによるネットワーク遅延の影響。
    *   **4. Lambda + Turso 構成 (本番)**: AWS Lambda のエンドツーエンドのレイテンシ。特に **コールドスタート発生時のオーバーヘッド (Init Duration)** を CloudWatch Logs の `REPORT` 行から集計し、許容範囲内（1秒未満）に収まっているかを確認します。
*   **Turso (libSQL) のリソース消費効率 (3, 4 のリモートDB構成)**:
    *   Turso の無料枠（行読み取り数）を枯渇させないためのクエリ設計になっているか。
    *   **測定方法**: `EXPLAIN QUERY PLAN` コマンドを使用して、`memory_search` や `memory_list` 実行時にインデックスが正しく使われ、全件スキャン（Table Scan）が発生していないかを検証します。また、Turso ダッシュボード上の行読み込み数の推移を監視します。

### ③ 価値評価 (Value)
日常的なAI開発において、どれだけ入力コストを削減できたかを定性・定量的に評価します。

*   **前提条件の再入力手間の削減度**:
    *   異なるLLMや新規セッション開始時に、コンテキストを手動でコピペ・入力する手間の削減。
*   **メタ記憶による自己評価ログの記録**:
    *   AIアシスタント自身に、「MemoryMCPの恩恵によって作業がスムーズに進んだケース」や「古い記憶がノイズになったケース」を `project_tag: meta` や `tag: eval` で記録させ、週末等に `memory_list` で振り返ります。

## 3. 「ローカル HTTP + Turso (Test 構成)」の動作テスト手順

現行のローカル HTTP サーバー実装のまま、コードを一切変更することなく、データベースのみリモートの Turso に切り替えて動作テストを行うことができます。

### 起動手順 (PowerShell)
1.  **環境変数の設定**:
    Turso のデータベース接続エンドポイントおよび認証トークンを設定します。
    ```powershell
    $env:DB_URL="libsql://your-database-name-username.turso.io"
    $env:DB_TOKEN="your-turso-auth-token"
    $env:API_KEY="your-local-api-key"
    $env:PORT="8080"
    ```
2.  **サーバーの起動**:
    ```powershell
    go run cmd/gnb-memorymcp/main.go server
    ```
3.  **動作確認**:
    `Authorization: Bearer <your-local-api-key>` ヘッダーを付与して `http://localhost:8080` に対して JSON-RPC リクエストを送信し、Turso へのデータ保存と検索が正しく行われることを検証します。
